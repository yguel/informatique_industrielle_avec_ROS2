Tester le code

Un code qui n’est pas testé est un code dont personne ne sait ce qu’il fait — y compris son auteur, dès qu’il y revient quelques semaines plus tard. Ce chapitre présente comment écrire des tests, comment les faire exécuter par ROS 2, et comment les faire exécuter automatiquement à chaque modification publiée.

Les quatre dernières sections s’appuient sur un projet support commun : la simulation MuJoCo du système 5 barres du cours (voir Description mécanique de la plateforme système 5 barres), dans laquelle les modèles géométriques direct et inverse sont à écrire, en C++ et en Python, et dont les tests sont fournis. La démarche suivie est celle du développement piloté par les tests : les tests existent avant le code, et échouent.
